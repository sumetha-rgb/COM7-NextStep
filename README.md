# COM7 NextStep: ระบบยืนยันตัวตนและแนวปฏิบัติผู้ใช้

เว็บแอป Next.js 15 (App Router) ใช้ NextAuth v4 สำหรับ session, Google Sheets สำหรับข้อมูลผู้ใช้และ OTP, Gmail OAuth สำหรับส่ง OTP และ Cloudinary สำหรับรูปโปรไฟล์

## บทบาทและเส้นทาง

| บทบาท | หน้าแรกหลังเข้าสู่ระบบ | สิทธิ์หลัก |
|---|---|---|
| Intern | `/rules` | ยืนยันข้อมูลและดูแนวปฏิบัติของ Intern |
| DVE | `/rules` | ยืนยันข้อมูลและดูแนวปฏิบัติของ DVE |
| Teacher | `/rules` | ยืนยันข้อมูลและดูแนวปฏิบัติของอาจารย์ |
| Admin | `/admin` | ภาพรวมผู้ใช้ ประวัติการแก้ไข และหน้าตัวอย่างแนวปฏิบัติ |

Middleware ตรวจ role สำหรับหน้าและ API และแต่ละหน้า/API ตรวจ session ซ้ำอีกชั้นหนึ่ง

## วิธีเข้าสู่ระบบและสมัคร

### Intern และ DVE

ระบบไม่มีแบบฟอร์มสมัครนักศึกษาใหม่ด้วยตนเอง ต้องมีข้อมูลผู้ใช้และเลขบัตรใน Google Sheet ก่อน (Intern อยู่ใน `INTERN`; DVE ใช้ข้อมูลใน `DVE` และข้อมูลที่ยืนยันแล้วอาจอยู่ใน `VerifiedUsers`)

1. เปิด `/login` เลือก “นักศึกษา”
2. กรอกชื่อ นามสกุล เลขบัตรประชาชน 13 หลัก และอีเมลที่รับ OTP ได้
3. ระบบตรวจเลขบัตรกับข้อมูลในชีตก่อนสร้าง OTP
4. กรอกรหัส 6 หลักจากอีเมลภายใน 10 นาที; ตอนยืนยันรหัส ระบบตรวจชื่อกับบัญชีอีกครั้ง
5. ผู้ใช้ที่ยังรอยืนยันจะไป `/confirm` ตรวจ/แก้ข้อมูลและยินยอม PDPA จากนั้นไป `/rules`

เลขบัตร 13 หลักใช้ตรวจสอบตัวตนก่อนส่ง OTP ไม่ใช่รหัสผ่านสำหรับเข้าสู่ระบบโดยลำพัง หากเลขบัตรไม่มีในชีตหรือไม่ตรง จะขอ OTP ไม่ได้

### เข้าซ้ำสำหรับ Intern และ DVE

มีสองทางเลือก:

- **เข้าสู่ระบบผู้ที่ยืนยันแล้ว** ที่ `/returning-login`: ใช้ชื่อ นามสกุล และเลขบัตร 5 ตัวท้าย บัญชีต้องมีสถานะยืนยันแล้วและมี `consentAt` ชื่อต้องตรงกับข้อมูลในชีต
- **ยืนยันแทน OTP**: หลังขอ OTP แล้ว หากไม่ได้รับอีเมล ให้เปิดตัวเลือกในหน้าขอรหัสและกรอกเลขท้าย 5 ตัว ระบบจะเข้าสู่ระบบได้เมื่อพบเลขดังกล่าวตรงกับบัญชี Intern/DVE เพียงบัญชีเดียวและบัญชีไม่ถูกปฏิเสธ

ทั้งสองวิธีใช้เลขท้าย 5 หลัก แต่เงื่อนไขต่างกัน: หน้า Login ซ้ำต้องระบุชื่อและบัญชียืนยันแล้ว ส่วนทางสำรอง OTP ไม่ขอชื่อและรับบัญชีที่ยังรอยืนยันได้ ควรใช้ทางสำรองเฉพาะเมื่อจำเป็น

### Teacher

**บัญชีเดิม:** เปิด `/login` เลือก “อาจารย์” แล้วเลือก “มีบัญชีแล้ว เข้าสู่ระบบ” กรอกชื่อ นามสกุล และอีเมลที่เคยยืนยัน ระบบกำหนดให้ยินยอม PDPA แล้ว

**สมัครครั้งแรก:** เปิด `/login` เลือก “อาจารย์” กรอกชื่อ นามสกุล และอีเมลเพื่อขอ OTP จากนั้นกรอกรหัสและยืนยันข้อมูลที่ `/confirm` บัญชีใหม่จะถูกเพิ่มในแท็บ `Teachers` ก่อนส่ง OTP หากการส่งอีเมลล้มเหลว แถวสมัครอาจถูกสร้างค้างไว้

### Admin

**สมัคร:** เปิด `/admin/register` กรอกชื่อ อีเมล Username (4–32 ตัวอักษร: a–z, 0–9, จุด, ขีดกลาง หรือขีดล่าง), Password (อย่างน้อย 8 ตัวอักษร) และรหัสเชิญ `ADMIN_REGISTRATION_KEY` บัญชีถูกบันทึกใน `AdminUsers` และพร้อมใช้งานทันที

**เข้าสู่ระบบ:** เปิด `/admin/login` และใช้ Username กับ Password การ Login ของ Admin ใช้รหัสผ่าน ไม่ได้ใช้ OTP อีเมล

## หลังยืนยันตัวตน

- `/confirm`: ผู้ใช้ทั่วไปตรวจ/แก้ชื่อ สถานศึกษา เบอร์โทร และข้อมูลที่แบบฟอร์มแสดง พร้อมอ่านและยินยอม PDPA ก่อนยืนยัน
- `/rules`: แสดงแนวปฏิบัติตาม role ของ session ผู้ใช้ Intern/DVE ต้องตอบคำถามแผนหลังฝึกงาน และให้เหตุผลเมื่อเลือก “ไม่สนใจ”
- ข้อมูลโปรไฟล์อ่านผ่าน `GET /api/me`; การแก้ไขและการยืนยันส่งผ่าน `PATCH /api/me` โดยแก้ได้เฉพาะข้อมูลของตนเองและมี AuditLog
- เปลี่ยนรูปโปรไฟล์ได้จากปุ่มโปรไฟล์เมื่อกำหนดค่า Cloudinary ครบ
- Admin ใช้ `/admin`, `/admin/audit` และ `/admin/rules-preview?role=Intern|DVE|Teacher` ตามสิทธิ์

## ตั้งค่าสภาพแวดล้อม

1. สร้าง Google Sheet และ Service Account เปิด Google Sheets API แล้วแชร์ชีตให้ service account ด้วยสิทธิ์ Editor
2. คัดลอก `.env.example` เป็น `.env.local` และกรอกค่าจริง ห้าม commit `.env.local`
3. ตรวจหัวคอลัมน์และลำดับคอลัมน์ของชีตให้ตรงกับ `lib/sheets.ts` และรูปแบบข้อมูล DVE ที่นำเข้า
4. ใช้ `npm run seed` เฉพาะชีตทดสอบที่เตรียมไว้ คำสั่งนี้สร้างแท็บ/เขียนหัวคอลัมน์ และเติมข้อมูลตัวอย่างเมื่อแท็บที่เกี่ยวข้องว่าง ห้ามรันกับชีต Production โดยไม่ตรวจผลกระทบก่อน
5. หากมีแถว Intern ใน `Users` ให้ตรวจแผนย้ายด้วย `npm run migrate:intern`; เมื่อตรวจจำนวนและผล dry run แล้ว จึงใช้ `npm run migrate:intern -- --apply` เพื่อคัดลอกแถว Intern ไป `INTERN`, ตรวจข้อมูลปลายทาง แล้วลบแถวต้นทาง
6. หากแท็บ `INTERN` ยังใช้หัวคอลัมน์มาตรฐานเดิม ให้ตรวจด้วย `npm run migrate:intern-layout`; หลังตรวจ dry run แล้วใช้ `npm run migrate:intern-layout -- --apply` เพื่อสำรองแท็บเดิมและแปลงเป็น layout Excel แบบ DVE
7. รัน `npm run dev` เพื่อเปิดเว็บในเครื่อง หรือ `npm run build` เพื่อตรวจ build สำหรับ deploy; `npm start` ใช้เปิด build ที่สร้างแล้ว

### ตัวแปรที่ใช้

| ตัวแปร | จำเป็น | ใช้ทำอะไร |
|---|---:|---|
| `SHEET_ID` | ใช่ | ID ของ Google Sheet |
| `GOOGLE_SERVICE_ACCOUNT_EMAIL` | ใช่ | อีเมล service account |
| `GOOGLE_SERVICE_ACCOUNT_PRIVATE_KEY` | ใช่ | private key; เก็บ `\n` ในไฟล์ env ได้ |
| `OTP_SECRET` | ใช่ | HMAC สำหรับเก็บ hash OTP; ใช้ secret สุ่มอย่างน้อย 32 ตัวอักษร |
| `NEXTAUTH_SECRET` | ใช่ | ลงนาม session; ใช้ secret สุ่มอย่างน้อย 32 ตัวอักษร |
| `NEXTAUTH_URL` | ใช่ | URL ของแอป เช่น `http://localhost:3000` หรือ URL Production |
| `GMAIL_CLIENT_ID` | ใช่สำหรับ OTP | Gmail OAuth client ID |
| `GMAIL_CLIENT_SECRET` | ใช่สำหรับ OTP | Gmail OAuth client secret |
| `GMAIL_REFRESH_TOKEN` | ใช่สำหรับ OTP | Gmail OAuth refresh token ที่ส่งอีเมลได้ |
| `GMAIL_FROM_EMAIL` | ใช่สำหรับ OTP | อีเมลผู้ส่งที่ตั้งค่าไว้ใน Gmail |
| `GMAIL_FROM_NAME` | ไม่ | ชื่อผู้ส่งอีเมล |
| `ADMIN_REGISTRATION_KEY` | ใช่สำหรับสมัคร Admin | รหัสเชิญสำหรับสร้างบัญชี Admin |
| `CLOUDINARY_CLOUD_NAME` | ไม่ | เปิดใช้รูปโปรไฟล์เมื่อกำหนดครบทั้งสามค่า |
| `CLOUDINARY_API_KEY` | ไม่ | Cloudinary API key |
| `CLOUDINARY_API_SECRET` | ไม่ | Cloudinary API secret |
| `APP_URL` | ไม่ | URL สำหรับลิงก์ในอีเมล; ถ้าไม่ตั้งจะใช้ `NEXTAUTH_URL` |
| `EMAIL_LOGO_URL` | ไม่ | URL โลโก้ในอีเมล |
| `DEMO_MODE` | ไม่ | ตั้งเป็น `true` เพื่อเปิดโหมด Demo; ค่าอื่นปิดโหมด |

สร้าง secret ได้ด้วย `openssl rand -base64 48` อย่าใช้ค่าเดียวกันสำหรับ `OTP_SECRET` และ `NEXTAUTH_SECRET`

Cloudflare Turnstile มี component และฟังก์ชันตรวจสอบในโค้ด แต่ปัจจุบันหน้า Login และ API ขอ OTP ยังไม่ได้เรียกใช้ และยังไม่มีตัวแปร Turnstile ใน `.env.example` จึงอย่าถือว่า CAPTCHA กำลังป้องกัน endpoint นี้อยู่

## โครงสร้าง Google Sheets

แท็บหลักที่ `npm run seed` เตรียมไว้:

| แท็บ | ข้อมูล |
|---|---|
| `INTERN` | ข้อมูลต้นทาง Intern; ใช้หัวคอลัมน์ Excel ชุดเดียวกับ DVE และเพิ่ม `profileImageUrl`, `profileEmail` ท้ายตาราง; เมื่อยืนยันแล้วสำเนารูปแบบมาตรฐานไป `VerifiedUsers` |
| `Users` | ผู้ใช้เดิม role อื่นที่ยังใช้โครงสร้างแถวทั่วไป; ระบบอ่านต่อเพื่อรองรับข้อมูลเดิม |
| `DVE` | ข้อมูลต้นทางนักเรียน ปวส.; อาจเป็น layout Excel ที่ระบบแปลงให้อ่านได้ |
| `VerifiedUsers` | ข้อมูลมาตรฐานของ DVE/Intern หลังยืนยัน เพื่อคง layout ต้นทางไว้ |
| `Teachers` | บัญชีอาจารย์ รวมถึงรายการสมัครใหม่ |
| `AdminUsers` | บัญชี Admin และ password hash |
| `Institutions` | รายชื่อสถานศึกษา |
| `Otp` | hash OTP, วันหมดอายุ, จำนวนครั้งที่กรอกผิด และเวลาส่งล่าสุด |
| `RateLimit` | สร้างโดย seed แต่ rate limit ปัจจุบันเก็บในหน่วยความจำของ process ไม่ได้อ่าน/เขียนแท็บนี้ |
| `AuditLog` | ประวัติการแก้ไขและการยืนยัน |

ห้ามสลับคอลัมน์หรือแก้หัวคอลัมน์ให้ไม่ตรงกับโค้ด เพราะระบบอ่าน/เขียนตามตำแหน่งคอลัมน์ ข้อมูลตัวอย่าง `admin@example.com` ในแท็บ `Users` ไม่ได้สร้างบัญชี Admin ที่ใช้ Login; บัญชี Admin ต้องอยู่ใน `AdminUsers` ผ่านการสมัครด้วยรหัสเชิญ

## พฤติกรรมและข้อจำกัดปัจจุบัน

- OTP มี 6 หลัก สุ่มด้วย `crypto.randomInt`, เก็บเป็น HMAC-SHA256, หมดอายุ 10 นาที, ใช้ครั้งเดียว, กรอกผิดได้สูงสุด 5 ครั้ง และขอใหม่ได้ทุก 60 วินาที
- คำขอ OTP บางกรณีตอบด้วยข้อความกลางเพื่อไม่เปิดเผยว่าพบบัญชีหรือไม่ แต่เลขบัตรนักศึกษา/ข้อมูลอาจารย์ไม่ตรง, อีเมลซ้ำ, ขอถี่เกินไป และข้อผิดพลาดการเชื่อมต่อจะแจ้งแยก
- จำกัดการขอ OTP ต่ออีเมล: ผู้ใช้ทั่วไป 5 ครั้ง/10 นาที, Admin 3 ครั้ง/10 นาที; มี rate limit ตาม IP เพิ่มเติม
- Rate limit ปัจจุบันเป็นหน่วยความจำในแต่ละ process จึงไม่แชร์ข้าม instance และอาจเริ่มนับใหม่เมื่อ process รีสตาร์ต เหมาะกับการใช้งานขนาดเล็กมากกว่าระบบหลาย instance
- Session มีอายุ 8 ชั่วโมง; role ของผู้ใช้มาจากข้อมูลฝั่งเซิร์ฟเวอร์และมีผลเมื่อเข้าสู่ระบบใหม่
- ผู้ใช้ที่ถูกปฏิเสธเข้า `/confirm` และ `/rules` ไม่ได้; Admin แก้สถานะ/role ผู้ใช้อื่นได้ แต่แก้สถานะ/role ของบัญชีตัวเองไม่ได้
- Google Sheets ไม่มี transaction; หากขั้นตอนที่เขียนหลายแท็บล้มเหลวกลางทาง อาจต้องตรวจและแก้ข้อมูลด้วยผู้ดูแล
- `/api/institutions` เปิดให้อ่านรายชื่อสถานศึกษาโดยไม่ต้อง Login เพื่อใช้ในแบบฟอร์ม
- การส่ง OTP พึ่ง Gmail OAuth; ตรวจสิทธิ์ refresh token, sender และโควตา Gmail หาก OTP ไม่ถึง
- Upload รูปใช้ Cloudinary รับเฉพาะภาพและจำกัดขนาดตาม route; หากไม่มี Cloudinary credentials endpoint จะตอบว่า service ยังไม่พร้อม

## ขั้นตอนตรวจสอบก่อนเปิดใช้งาน

ทดสอบบน Google Sheet และอีเมลสำหรับทดสอบที่แยกจาก Production เท่านั้น การขอ OTP ส่งอีเมลจริง และการสมัครอาจเขียนข้อมูลลงชีต

### นักศึกษาและอาจารย์

1. เตรียม Intern และ DVE ที่มีเลขบัตรทดสอบในชีต รวมถึงอีเมลทดสอบที่รับได้
2. ทดสอบขอ OTP ด้วยข้อมูลตรง แล้วกรอก OTP ที่ถูกต้อง; ตรวจว่าเข้าสู่ `/confirm` และยืนยัน PDPA แล้วไป `/rules`
3. ทดสอบเลขบัตร/ชื่อไม่ตรง, OTP ผิด, OTP หมดอายุ, OTP ใช้ซ้ำ และขอรหัสซ้ำก่อนครบ 60 วินาที
4. ทดสอบรหัสท้าย 5 หลักที่ถูก/ผิด, ชื่อที่ถูก/ผิด, บัญชียังรอยืนยัน, บัญชีถูกปฏิเสธ และเลขท้ายที่ซ้ำกัน
5. ทดสอบผู้ใช้ Intern/DVE ที่ยืนยันแล้วผ่าน `/returning-login`
6. ทดสอบ Teacher เดิมด้วยชื่อ+อีเมล และสมัคร Teacher ใหม่ด้วยอีเมลทดสอบ; ตรวจแถวใน `Teachers` และผลเมื่อการส่งอีเมลสำเร็จ/ล้มเหลว

### Admin และสิทธิ์

1. สมัคร Admin ในชีตทดสอบด้วยรหัสเชิญ แล้ว Login ด้วย Username/Password ที่ถูกและผิด
2. ลองเข้า `/admin` และ `/api/admin/*` โดยไม่มี session และด้วย role ที่ไม่ใช่ Admin
3. ตรวจว่า role ผู้ใช้ทั่วไปเข้าได้เฉพาะ `/confirm`, `/rules` และ API โปรไฟล์ของตนเอง
4. ตรวจแก้ไข/อนุมัติ/ปฏิเสธผู้ใช้, ประวัติ AuditLog, การกรองและ pagination

### การตั้งค่าภายนอก

1. ตรวจ Google Sheets API และสิทธิ์ service account ด้วยการอ่าน/เขียนในชีตทดสอบ
2. ตรวจ Gmail OAuth ส่ง OTP ถึง mailbox ทดสอบ
3. ทดสอบรูปโปรไฟล์เมื่อกำหนด Cloudinary ครบ
4. หากต้องใช้ Turnstile ต้องเชื่อม component และเรียก `verifyTurnstile` จากหน้า/API ก่อน แล้วจึงเพิ่มการทดสอบ token ผ่าน/ไม่ผ่าน; checklist เดิมที่ระบุว่าไม่มี token ต้องได้ 400 ยังไม่ตรงกับโค้ดปัจจุบัน

## โหมด Demo

ตั้ง `DEMO_MODE=true` แล้วเปิด `/demo` เพื่อเลือก role และดูหน้าในโหมดตัวอย่าง โหมดนี้ข้าม OTP และใช้ข้อมูลตัวอย่าง จึงห้ามเปิดบน Production โหมด Demo ไม่ได้ทดสอบการเชื่อม Google Sheets, Gmail, OTP, การสมัครจริง หรือการยินยอมที่บันทึกลงระบบ
